# 実装ロードマップ

更新日: 2026-07-13

## 最終ゴール

ユーザーが所有する Grim Dawn のローカルゲームデータと、次のいずれかのビルド入力を使い、特定ビルドがどの敵のどの攻撃列に弱いか、その理由と有効な改善候補を根拠付きで説明できるローカルツールを完成させます。

ビルド入力:

1. `player.gdc` の読み取り専用インポート
2. Grim Dawn Build Calculator の共有URL
3. 手入力の防御スナップショットJSON

最終出力は、単一の生存スコアではなく、少なくとも次を含みます。

- 対象のゲーム版、チャンネル、難易度、敵レベル、コンテンツ条件
- 危険な敵、フェーズ、スキル、攻撃列のランキング
- 単発、多段、デバフ後の追撃、床・複数敵との重なりの分類
- OA/DA、耐性、装甲、吸収、デバフを通した計算の中間値
- 平常時、主要バフ時、主要デバフ時の比較
- 防御値を変更した場合の感度分析と改善候補
- ゲームデータ、公式仕様、実測、推定、未確定事項の区別
- Grim Tools の対応するビルド・アイテム・モンスターページへの参照

## 完了の定義

最終ゴールは、次をすべて満たしたときに完了とします。

1. クリーンな環境で、ユーザーが指定または自動検出したゲームインストールからデータセットを再生成できる。
2. Base Game、GDX1、GDX2および将来拡張を、明示した優先順位で統合できる。
3. 実在する `player.gdc` と Grim Tools共有URLの双方から、同一の内部Buildモデルを生成できる。
4. 選定した代表敵群について、全フェーズと主要攻撃列を正規化し、対象ビルドへの被ダメージを計算できる。
5. 少なくとも一つの単発、一つの多段、一つのデバフ後追撃、一つの複数要因遭遇を実測と照合できる。
6. 代表シナリオの回帰テストが通り、未対応項目は黙って近似せず明示される。
7. 新しいゲームデータに対して差分と再検証対象を出し、旧データセットを上書きせず併存できる。
8. ゲーム由来ファイル、セーブ、Grim Toolsの大量複製をリポジトリや配布物へ含めない。

## 実装原則

- ローカルゲームデータを一次データ源とし、Grim Toolsの非公開API、DOM、内部JavaScriptへ中核機能を依存させません。
- Raw値、正規化値、変換規則、出典、ゲーム版を追跡可能にします。
- `player.gdc`、ARZ、ARCは常に読み取り専用で扱い、入力ハッシュを記録します。
- 不明なエンジン挙動を推測値で埋めず、`unknown` または信頼度付き近似として返します。
- 各マイルストーンは「実装 → 自動テスト → 実データ検証 → 文書更新」の一巡で完了します。
- 広い網羅性より、まず「1ビルド × 1敵 × 1攻撃列」の説明可能な縦切りを優先します。

## 成果物の構成目標

```text
game install / player.gdc / Grim Tools URL
                  |
                  v
        read-only input adapters
                  |
                  v
 raw records + provenance + version manifest
                  |
                  v
 normalized game/build/encounter models
                  |
                  v
 deterministic combat and timeline engine
                  |
                  v
 ranking + sensitivity + evidence report
```

中核モデルは入力元や表示層から独立させます。これによりGrim Tools URL連携が一時的に壊れても、ローカル抽出、セーブ取込、解析は継続できます。

## M0: 実装基盤と実データ・スモークテスト

目的: この端末の実データを安全に読めることを、最小の自動テストで証明します。

実装:

- 使用言語、CLI、テストランナー、依存管理を固定する
- インストールパスの明示指定とSteam標準配置の検出
- ARZ/ARC/セーブを変更しない読み取り専用ガード
- dataset manifestの初版
- Base、GDX1、GDX2、GDX3、日本語localizationの存在・ハッシュ確認
- 小さな手製fixtureとCI向けゲーム非依存テスト

検証対象:

- `database/database.arz`
- `gdx1/database/GDX1.arz`
- `gdx2/database/GDX2.arz`
- `resources/Text_EN.arc` と `resources/Text_JA.arc`

完了条件:

- `doctor` 相当のコマンドが、検出パス、DLC、ファイルサイズ、SHA-256、警告を機械可読形式で返す。
- ゲームファイルの変更時刻とハッシュが実行前後で変化しない。
- ゲーム未導入環境でもfixtureテストが通る。

## M1: 一撃計算の説明可能な縦切り

目的: データ抽出より先に、戦闘計算の正しさと説明形式を固定します。

実装:

- `BuildDefenseSnapshot` と `EnemySkill` のfixture
- OA対DAの命中・クリティカル判定
- ダメージ種別ごとの耐性と耐性低下
- 部位別装甲、装甲吸収率、各種吸収の適用
- 最小、平均、最大と部位別結果
- 各段階の入力・式・出力を残す説明トレース
- 未対応効果を検出して警告する仕組み

完了条件:

- 公式Combat Guideの装甲例を回帰テストで再現する。
- 一つの敵攻撃に対する被ダメージ内訳を、入力から最終HP差分まで説明できる。
- 計算順序を変えると失敗するテストを持つ。

## M2: ARZ/ARC抽出と版付きデータセット

目的: ゲーム本体から、再現可能で差分可能な正規化データを生成します。

実装:

- ARZレコードの損失を抑えたRaw表現
- Base → GDX1 → GDX2 → 将来拡張の上書き規則
- ARCから英語・日本語localization tagを解決
- Monster → phase → skill → controller → chained skillの参照追跡
- アイテム、接辞、セット、コンポーネント、増強剤の最低限の索引
- 敵レベル、難易度、分類に依存する値の解決
- dataset manifestと正規化ルールIDの保存
- 旧・新dataset間の意味的差分

最初の縦切り:

- 代表HeroまたはBoss一体
- 主要スキル一つ
- 英語名・日本語名
- Rawレコードから正規化JSONまでの追跡

完了条件:

- 選定したNemesis一体の全フェーズと攻撃候補を正規化JSONへ出せる。
- 任意の正規化フィールドから、元ARZ、レコードパス、原フィールド、変換規則へ戻れる。
- 同じ入力と抽出器版から同じ出力ハッシュを再生成できる。
- パッチ差分で敵・スキル・重要フィールドの追加、削除、変更を区別できる。

## M3: 攻撃列・状態変化・実測照合

目的: 「ワンパン」に見える事象を、時間軸上の原因へ分解します。

実装:

- attack timeout / delay / chance / range / chain
- projectile、多段、DoT、ground effect、召喚物の表現
- Sunder、耐性低下、DA低下、CC、バフ解除の状態遷移
- 同時または近接フレームの複数ヒット
- 動画・手動観測を保存するObservation形式
- 静的予測と実測の誤差レポート

分類:

- `single_hit`
- `shotgun`
- `combo`
- `overlap`
- `recovery_failure`
- `unknown`

完了条件:

- 一つの遭遇を上記分類のいずれかへ、根拠と信頼度付きで分類できる。
- デバフ適用前後の攻撃をタイムラインで再計算できる。
- 静的DBだけで確定不能な差を、エラーではなく未確定事項として報告できる。

## M4: `player.gdc` 読み取り専用インポート

目的: 実キャラクターから解析用Buildモデルを生成します。

実装:

- Steam Cloudとローカルセーブの検出
- 入力コピーまたはメモリ上での読み取りとSHA-256記録
- キャラクター版の検出と未対応版の拒否
- 装備、接辞、コンポーネント、増強剤、スキル、星座の解決
- 平常時と選択可能な一時バフ時の防御スナップショット生成
- 個人セーブを含まない合成fixtureと、許諾された匿名fixture

完了条件:

- 少なくとも一つの実在セーブからBuildモデルを生成できる。
- ゲーム内またはGrim Toolsへ同じセーブを読み込んだ結果と主要項目が一致する。
- 元セーブのハッシュと更新日時が実行前後で変化しない。
- 版不一致、破損、MODキャラクターを安全に検出する。

## M5: Grim Dawn Build Calculator連携

目的: Grim Toolsを置き換えず、共有ビルドの入口と照合先として活用します。

実装:

- Grim Tools共有URLの妥当性検査とcanonical ID抽出
- 公開・安定して取得できる範囲だけを使うURL adapter
- 取得結果から、M4と同じBuildモデルへの変換
- アイテムDB、モンスターDB、Build Calculatorへの外部参照リンク生成
- ローカルゲーム版とGrim Tools表示版の不一致警告
- レート制限、キャッシュ、タイムアウト、取得失敗時の明示
- 保存済みfixtureによるネットワーク非依存の契約テスト

非目標:

- サイト全体のクロールまたは複製
- DOMやminify済みJavaScriptを中核データ源にすること
- 非公開APIが永続すると仮定すること
- Grim Toolsと同等のフルビルドエディタ

完了条件:

- 対応する共有URLからBuildモデルを生成できる。
- 同じビルドを `player.gdc` と共有URLから入力した場合、差分をフィールド単位で説明できる。
- ネットワークまたはサイト仕様変更時も、M0–M4と解析機能が影響を受けない。

## M6: Encounter Advisor MVP

目的: 一つの実ビルドへ、複数の代表的な敵・攻撃列を適用して弱点を説明します。

実装:

- Nemesis、Celestial、代表Bossの検索・比較
- キャンペーン、単体ボス、SRのシナリオ設定
- 危険攻撃のランキング
- 耐性超過、DA、装甲、吸収、CC耐性等の感度分析
- 平常時・バフ時・デバフ時の比較
- 根拠、信頼度、未確定事項を含むJSONと人間向けレポート

完了条件:

- 「このビルドは、どの敵のどの攻撃列に、なぜ弱いか」を中間計算付きで回答できる。
- 改善候補ごとに、どの攻撃への被害がどの程度変わるかを示せる。
- 少なくとも4種類の攻撃分類を代表fixtureまたは実測で回帰試験する。

## M7: 更新運用とリリース可能化

目的: ゲーム更新、公開テスト、将来拡張へ安全に追随できる状態にします。

実装:

- stable / public_testを分離したdataset管理
- schema migrationと後方互換方針
- 新ARZ検出時の差分生成とclaim再検証キュー
- セーブ形式変更を検知する回帰テスト
- CLI使用手順、トラブルシューティング、配布境界の文書化
- 公開前のCrate Entertainment利用条件・ファンコンテンツ方針確認

完了条件:

- 新datasetを旧datasetと併存させて生成・比較できる。
- 変更された敵、スキル、防御計算要素と、再検証が必要なclaimを列挙できる。
- ゲーム由来データなしの配布物から、所有ゲームを使ってローカル再生成できる。

## マイルストーン間の依存関係

```text
M0 -> M1 -> M2 -> M3 -> M6 -> M7
             \       /
              M4 -> M5
```

- M0完了後、M1とM2の準備は並行できますが、最初の統合はM1の計算契約を先に固定します。
- M4はM2のアイテム・スキル索引へ依存します。
- M5はM4で確定したBuildモデルを再利用します。
- M6はM3の攻撃列と、M4またはM5の実ビルド入力を必要とします。

## 各実装セッションの標準ループ

次セッション以降は、原則として一回に一つの最小チケットを完了させます。

1. 対象マイルストーンと一つの観測可能な成果を選ぶ。
2. 先に受け入れ条件と失敗するテストを置く。
3. 最小実装を行う。
4. fixtureテストを実行する。
5. 可能なら所有ゲームの実データで読み取り専用検証を行う。
6. 期待値との差を、コード不具合・モデル不足・データ不足・版差・エンジン不明へ分類する。
7. 修正後に全回帰テストを実行する。
8. 仕様、マッピング、既知制約、次の一手を文書へ反映する。

チケットは次を必須項目とします。

- 目的
- 対象範囲と非対象範囲
- 入力・出力契約
- 受け入れ条件
- fixtureと実データ検証
- 既知リスク
- 変更する文書

## 最初の実装チケット

次セッションはM0の「インストール診断とdataset manifest生成」から開始します。

範囲:

- Steam標準配置または明示パスからGrim Dawnを検出
- Base、GDX1、GDX2、GDX3、英語・日本語ARCの存在確認
- ファイルサイズ、更新日時、SHA-256をJSONへ出力
- stable / public_testはユーザー指定または検証可能な根拠がない限り断定しない
- 入力ファイルを変更しないことをテスト

このチケットではARZ内容の抽出、セーブ解析、Grim Toolsアクセスは行いません。まず安全で再現可能な入力境界を固定します。

## 当面やらないこと

- Grim Toolsを置き換えるフル装備／スキルエディタ
- 全敵を最初から手作業で攻略記事化
- 出典やゲーム版のないTier表
- 実測なしの単一「生存スコア」
- ゲームファイル、セーブ、大量の抽出データの再配布
- ゲームプロセスへの注入、メモリ書換え、自動操作
- セーブや共有スタッシュへの書込み
